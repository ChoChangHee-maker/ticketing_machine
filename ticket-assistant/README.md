# 티켓팅 도우미

React + Vite 화면과 로컬 Node.js/Playwright 실행기로 구성한 Windows 티켓팅 보조 프로그램입니다. 기존에 잘못 만든 ONSTAGE 판매 사이트와 분리된 프로젝트입니다.

## 실행

상위 폴더의 **프로그램 실행.cmd**를 더블클릭합니다. 브라우저에 프로그램 화면이 열립니다. 실행 창을 닫으면 프로그램이 종료됩니다.

```powershell
cd ticket-assistant
npm install
npm run browser:install
npm run dev
```

화면: http://127.0.0.1:5174/ (다른 프로그램과의 포트 충돌을 피하기 위해 5174 사용)

프로덕션 실행: `npm run build` 후 `npm start` → http://127.0.0.1:4318/

## 사용 순서

1. 멜론티켓 / NOL 티켓 / YES24 / 샤롯데씨어터 / 세종문화회관을 단일 또는 다중 선택합니다.
2. 티켓처를 선택하면 해당 사이트의 전용 브라우저가 열립니다. 로그인을 직접 진행합니다.
3. 로그인 연결에서 상태를 확인합니다. 공식 티켓처 화면의 **보이는 로그아웃 메뉴**를 확인한 경우에만 로그인 확인됨으로 표시합니다. 이전 탭의 표시나 SSO 서비스의 로그인만으로 성공을 표시하지 않습니다. **새로 확인**은 별도 확인 탭에서 공식 페이지를 갱신합니다. 계정 메뉴를 열어야 로그아웃이 보이면 갱신된 창에서 메뉴를 열고 자동 확인을 기다립니다.
4. 티켓처별 실제 공연 URL, 관람 날짜와 회차, 선호 구역 및 열, 좌석 수, 연석 여부를 설정합니다. URL 없이 준비 설정만 저장할 수도 있습니다.
5. 조건을 설정하고 로그인 확인이 완료되면 실행할 수 있습니다. 예약 실행은 한국 시간 기준이며 프로그램과 PC가 켜져 있어야 합니다.
6. 선택한 티켓처들을 함께 진행하고 한 곳에서 좌석을 클릭하기 시작하면 다른 곳의 추가 클릭을 멈춥니다. 로그인·보안 확인·결제는 직접 처리합니다. 좌석 클릭 후 상태를 읽지 못하면 성공 대신 직접 확인 필요로 표시합니다.
7. 로그인·보안 확인이나 찾지 못한 항목 때문에 멈추면, **실행 기록 → 화면 보기**에서 직접 진행합니다. 이어갈 단계를 골라 **이 단계부터 이어가기**를 누르면 같은 예매창을 사용합니다. 예를 들어 날짜를 직접 선택했다면 회차 선택부터 이어갑니다. 좌석을 클릭한 뒤에는 자동 이어가기를 제공하지 않습니다.

로그인 상태는 보이는 화면을 주기적으로 읽습니다. 실행 전과 예약 대기 후에는 공식 확인 페이지를 다시 불러옵니다. 바로 갱신한 확인 탭은 30초 이내에 한해 재사용하되 표시를 다시 읽습니다. 서버 측 세션 유효성을 보장하는 공식 인증 API 검증은 아닙니다. 숨겨진 메뉴나 사이트의 화면 구조 때문에 판정할 수 없으면 미확인으로 남습니다.

## 현재 확인 범위

- React 화면 프로덕션 빌드와 로그인 만료/이전 탭 혼동 방지, 인증 후 같은 창에서 이어가기, 지연 로딩, 다중 티켓처 클릭 제한, 좌석 변경 감지, API 접근 제어, 설정 저장, 실행 중지 등 모듈/API 테스트 통과. 테스트는 가상 화면 응답을 사용하며 실사이트 검증을 대신하지 않습니다.
- 2026-09-10 공개 페이지 검사: 멜론티켓, NOL, 샤롯데씨어터, 세종문화회관 HTTP 200. NOL의 현행 `nol.yanolja.com` 주소 반영. YES24는 STCLab 보안 확인 페이지로 이동하여 로그인 가능 여부는 미확인.
- **실제 사용자 계정 로그인 성공 및 5개 티켓처의 실공연 좌석 선택은 아직 검증하지 않았습니다.** 이 환경에 연결된 조작 가능한 브라우저와 사용자 로그인 세션이 없습니다. 계정 로그인은 공식 창에서 사용자가 진행한 뒤 프로그램이 표시된 상태를 판정합니다.
- 현재 예매 실행기는 공식 도메인의 DOM 항목을 이용하는 공통 엔진입니다. 모든 공연에 대해 동작이 검증된 전용 어댑터가 아닙니다. 날짜는 전체 날짜를 가진 속성, 회차는 정확한 시간, 구역은 정확한 구역명으로 찾습니다. 실제 공연 URL을 받은 뒤 해당 화면에 맞춘 연결과 실동작 확인이 필요합니다.
- 좌석에 구역·열·번호 정보가 없거나 좌석도가 캔버스인 경우 자동 선택을 중단합니다. 대기열 우회, 보안문자 처리, 자동 결제 기능은 없습니다. 좌석 클릭과 서버 선점·결제 완료는 다른 상태입니다.

## 공연별 화면 연결

화면 연결 메뉴에서 예매하기, 날짜, 회차, 구역, 좌석의 Playwright/CSS 선택자를 지정할 수 있습니다. 기본 자동 탐색으로 읽히지 않는 공연을 연결하기 위한 고급 설정입니다. 실제 페이지에서 확인한 항목만 사용합니다.

직접 지정한 선택자는 기본 탐색보다 우선하며, 해당 항목이 없다고 다른 버튼을 대신 누르지 않습니다. 항목이 늦게 나타나면 최대 6초 동안 화면을 읽어 기다립니다. 이 과정에서 페이지를 반복 새로고침하지 않습니다.

- 날짜: `{date}` → `2026-10-17`, `{dateCompact}` → `20261017`, `{day}` → `17`
- 회차: `{time}` → `19:00`
- 구역: `{zone}` → 현재 선호 구역
- 예: `[data-date="{date}"]`, `[data-time="{time}"]`, `[data-zone="{zone}"]`
- 좌석은 `title`/`aria-label`의 `1층 A구역 3열 12번`, 또는 `data-zone`, `data-row`, `data-seat-no` 속성으로 해석합니다.
- 선택 결과는 `aria-selected`, `aria-pressed`, `data-selected`, `selected`/`on` 클래스 등을 읽습니다. 확인할 수 없으면 직접 확인 필요 상태로 멈춥니다.

## 파일과 개인정보

- `src/`: React 사용자 화면
- `shared/`: 티켓처 정의, 설정 검증, 로그인 판정, 좌석 조건
- `server/`: 로컬 API, 전용 브라우저 관리, 예매 실행기
- `tests/`: 모듈/API 테스트 (실계정 로그인 테스트 아님)
- 로그인 프로필: `%LOCALAPPDATA%\TicketAssistant\profiles\<티켓처>`
- 저장 설정: `%LOCALAPPDATA%\TicketAssistant\settings.json`
- 로그인 정보는 OneDrive 작업 폴더로 복사하지 않습니다. 브라우저 프로필을 공유하지 마세요.
- API는 루프백 주소에만 바인딩하고 프로그램 토큰 및 요청 출처를 검사합니다.

## 검증 명령

```powershell
npm run check
npm test
npm run build
npm run probe
```

`probe`는 공개 홈페이지 접속 검사이며 로그인 성공 여부를 검사하지 않습니다. 결과는 `.local/connectivity.json`에 저장됩니다.

확인한 공식 자료: [멜론 예매 안내](https://ticket.melon.com/customerservice/howto.htm), [NOL 티켓](https://nol.yanolja.com/ticket), [세종문화회관](https://www.sejongpac.or.kr/), [Playwright BrowserContext](https://playwright.dev/docs/api/class-browsercontext).
